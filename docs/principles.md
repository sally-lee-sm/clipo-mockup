# Principles
1. 새 화면은 백지에서 그리지 말고 레퍼런스화면에서 가장 가까운 확정 화면을 복제해 시작한다. 헤더·좌측 NB·탭 밴드·푸터·디자인 토큰·컴포넌트는 그대로 따른다. 무엇이 확정 기준인지는 서비스 폴더 CLAUDE.md의 개발 화면 기준 표가 권위 소스.
2. 팝업보다 인라인: 핵심 입력·선택·다음 단계는 페이지 인라인/전환(스텝)으로. 모달은 되돌릴 수 없는 짧은 확인이나 아주 짧은 보조 입력에만.
3. 같은 위계 UI 일관성: 같은 그룹 라벨은 어미·형태 통일(평행성). 탭·세그먼트 활성 시 font-weight 변화 금지(색+밑줄로만 구분, 들썩임 방지). 공유 컴포넌트는 페이지 간 1:1 동일.
4. 모든 클릭 요소는 버튼 콘텐츠 중앙정렬 5종 세트: inline-flex; align-items:center; justify-content:center; line-height:1; vertical-align:middle.
5. 브랜드 표기는 항상 대문자 CLIPO / HIAI. 혼합표기 HiAI·소문자 Clipo/hiai 금지.
6. 본문 16px·레이블 14px 이상(읽고 수정하는 본문은 반드시 16px↑). Alert/Info/Warning 박스 좌측 컬러 띠(border-left) 금지, 배경+아이콘만. 버튼 레이블은 단어형(저장/추가/삭제).
7. 정보 흐름: 조작 컨트롤(스코프·옵션)은 영향 필드 뒤, 설명·잠금·경고 안내는 영향 필드 앞/상단.
8. 가짜 데이터 금지: 시연 케이스는 실제 학급·학생 구성 안에서 상태만 바꾼다. 실제에 없는 가짜 반/학생을 끼우지 않는다.
9. 라벨·문구·UI 패턴을 바꾸기 전 grep으로 동일 패턴 전수 검색 후 사전 보고한다. 화면 마무리 직전 docs/checklist.md를 한 줄씩 점검하고 결과를 보고한다(조용히 통과 금지).
