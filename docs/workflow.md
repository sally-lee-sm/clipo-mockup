# 목업 작업 워크플로 (일관성·확인·이어받기)

> 라벨·문구·UI 패턴을 만들거나 바꾸기 전, 그리고 화면을 넘길 때 이 문서를 따른다.

## 변경 영향 범위 체크 (필수)
목업은 기획 일관성이 핵심 — 한 곳 수정에 매몰돼 같은 패턴을 빠뜨리면 안 된다.
1. 텍스트·라벨·UI 패턴을 바꾸기 **전에 grep으로 동일 패턴 전수 검색**(`clipo/레퍼런스화면/`·`hiai/레퍼런스화면/` + 작업 중 파일들).
2. 발견 위치를 **사전 보고**: "'점수 (총점/등급)'이 6개 파일 12군데 있어요. 전부 바꿀까요, 일부만?"
3. "여기만"이라고 하면 → 다른 곳은 손대지 않고 차이를 명시.
4. 공유 컴포넌트(헤더·NB·탭밴드·반복 모달)·메인↔`_annotated` 동일 파일은 한 곳 바꾸면 전수 동기화.

## 능동 확인 원칙 (항상)
- **파일을 바꾸기 전·확정하기 전에는 먼저 묻는다.** 여러 곳을 바꿔야 하면 위 grep 전수검색 → "어디어디 있어요, 다 바꿀까요?"를 **먼저 보고**하고 진행. 사용자가 짚어주기 전에 챙긴다.
- 지침이 모호하거나 선택지가 갈리면 추측하지 말고 한 줄로 물어본다.

## 산출물 규칙
- 기본 형식: **단일 HTML 파일**(인라인 CSS + Tailwind CDN + Lucide 아이콘) — 빌드 불필요, 어디서나 브라우저로 열림.
- **하나의 기능 = 하나의 파일.** 탭·스텝·상태 전환은 한 파일 안에서 JS로.
- 작업 중엔 **preview(미리보기)로만** 확인, "저장해줘" 할 때만 `output/`에 저장. 완료 보고는 스크린샷 대신 **클릭 가능한 미리보기 링크**로.
- 파비콘·폰트·토큰은 서비스 폴더 CLAUDE.md 스펙 그대로(CLIPO=Pretendard GOV·`#416bff` / HIAI=NanumSquareRound·`#7E44FB`).

## 마무리 점검
화면을 "다 됐다"고 하기 직전, **`docs/checklist.md`를 한 줄씩 점검한 뒤 결과를 보고**한다. 조용히 통과시키지 말 것 — 통과/걸린 항목을 짧게 알리고, 고친 부분은 무엇을 왜 고쳤는지 같이 말한다. 애매한 항목은 임의 판단하지 말고 물어본다.

## 이어받기
- 진행 중 화면을 이어받을 땐, 해당 서비스의 `이어받기/` 폴더에서 그 화면의 맥락 문서(`context_*.md` / `HANDOFF_*.md`)를 먼저 읽는다 — "어디까지 했는지 / 왜 이렇게 정했는지 / 건드리면 안 되는 것".
- 새 화면을 누군가에게 넘길 땐 `../이어받기-템플릿.md` 양식으로 같은 문서를 남긴다.
- (Trellis 일지 `docs/sessions/`가 "그날 뭘 왜 했나"를 자동으로 쌓지만, 진행중 화면의 핸드오프는 위 이어받기 문서로 남긴다.)
